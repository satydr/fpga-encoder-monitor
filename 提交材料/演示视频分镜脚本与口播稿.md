## 〇、拍摄前必做（留 40 分钟，别跳过）

| # | 事项 | 为什么 |
|---|---|---|
| 1 | **把 `.bin` 烧进 SPI Flash，JP2 跳 QSPI，断电重启确认程序还在** | JTAG 下载的 bit 断电即丢，会退回出厂 `EGO1_BIST_35T.bin`（D24 亮 ≠ 你的程序在跑）。**视频里一断电就露馅** |
| 2 | **排查 `status=0x02`（丢脉冲）常亮问题** | 真机日志里 2663/3054 帧都是 0x02。若拍摄时报警灯一直亮，评委第一反应是"你在误报"。见文末【排错】 |
| 3 | 接上 Z 相（编码器第 5 根线 → J5-17 / E15），确认不再误报 | 未接时 `z_seen=0`，丢脉冲功能降级；接上后才有完整闭环演示 |
| 4 | 电机与编码器**机械固定**（同心度），拧调速器时轴不打滑 | 打滑会导致转速跳变，画面很难看 |
| 5 | PC 打开 `uart_monitor.py -p COMx -b 115200`，确认在收数 | 镜头 7 要用 |
| 6 | 手机横屏 1080p/60fps，**关掉美颜和滤镜**，找个亮的地方 | 数码管和 OLED 要拍清楚 |

## 四、拍摄排错速查

| 症状 | 原因 | 处理 |
|---|---|---|
| **一上电 D24 亮、数码管有显示，但波形不动** | 跑的是出厂 `EGO1_BIST_35T.bin` | 烧 `.bin` 到 SPI Flash，JP2 跳 QSPI |
| **一个数也数不到** | 编码器与板子没共地，或编码器供电不足 | 编码器 OV 再引一根到 J5-33/34；VCC 接外部 12V/6V，**不能接板载 3.3V** |
| **数码管显示 `8520`** | 位序反了 | 一行修正（`<<` 改 `>>`），见报告 6.2 节 |
| **PC 改阈值没反应** | `cmd_rx` 帧头解析 | 已修复（AA + 55 两步）；确认烧的是最新 bit |
| **清报警时灵时不灵** | 解除武装逻辑 | 已修复（`ov_disarm`/`pl_disarm`）；确认烧的是最新 bit |
| **`status` 长期停在 `0x02`** | 丢脉冲持续置位 | 【高优先级排查】见下 |

### 【高优先级排查】status 长期为 0x02

真机日志显示 3054 帧里有 2663 帧状态为 `0x02`（丢脉冲），这意味着报警在正常运行期间几乎常亮。拍摄前必须查清，否则视频里报警灯一直亮，说服力直接反转。

按顺序查：

1. **Z 相是否真的接上了**：若已接，`z_seen=1`，此时 `z_gap_cnt > CPR + z_tol` 会判丢脉冲。核对编码器的**每转线数 CPR** 与代码里的常量是否一致——CPR 写大了就会一直判丢。
2. **转速是否真的平稳**：电机稳态 500±5 转，若调速器抖动大，Z 相间隔会忽长忽短，超出 `z_gap_tol`。
3. **把 `z_gap_tol` 调大再试**（PC 在线可改），看 `0x02` 是否消失 → 若是纯阈值问题，拍摄前设一个合理值。
4. **若 Z 相未接却仍报 0x02**，说明另有判据在触发（非法跳变），需要回放波形确认——这种情况下宁可先不接 Z 相拍摄（此时功能降级、不报警），把丢脉冲演示放在镜头 5 用"拔线"的方式单独呈现。
